# M8.1：API 超时修复

## 原因与修复

「测试连接」通过真实 Responses API 发送合成窗口判定。原先的 3 秒上限包含建立连接和模型生成回复；首次连接尚未收到回复，客户端就取消了请求。

本机实测同一已保存密钥、同一模型：

| 测试 | 结果 |
| --- | --- |
| 模型访问权限 | HTTP 200，密钥和模型有效 |
| 新连接，3 秒请求上限 | 3.023 秒被取消，显示「AI 请求超时」 |
| 新连接，15 秒请求上限 | 5.201 秒成功，合成学习窗口判定为 on_task |
| 发布后，读取 M8.1 配置与已保存密钥 | 8.364 秒成功，确认请求上限为 15 秒 |
| 已建立连接后的判定 | 实测约 1.7–2.3 秒 |

用户确认后，将 `ai.requestTimeoutSeconds` 从 3 改为 15。回复提前到达就立即处理；等待期间保持待判定，超时或失败继续安全降级，切换窗口仍取消旧请求。网络和服务处理都可能影响请求耗时，应与认证失败区分处理，见 [OpenAI 错误说明](https://developers.openai.com/api/docs/guides/error-codes)。

没有修改模型、密钥、规则、界面或判定代码。诊断只发送合成数据，密钥仅在本机内存读取，不进入命令行、日志或提交。

## 验证与手动步骤

- Release 构建：0 警告、0 错误。
- 全部 .NET 测试：213 项通过，包含超时降级、调用者取消与过期窗口回复检查。
- 发布包使用 `dist/StudyGuardian-M8.1`，`Start.cmd` 指向新版；旧目录保留。
- 原程序通过正常关闭完成保存，5 个数据文件复制后逐个校验一致；新版已打开且启动时没有新增会话或活动事件。发布归档不含个人数据，文件清单和 ZIP 校验通过。
- 打开设置，使用已保存的 Key 和模型点击「测试连接」，应看到成功及实际耗时；开始测试会话后，未知窗口停留达到防抖时间会调用 AI，切换窗口时旧请求仍失效。
